# SINTEZ Ontology Mathematics — Repository Constitution

## 1. Назначение репозитория

Этот репозиторий является публичным каноническим контуром ontology-first математики SINTEZ.

Основное направление вывода:

ONTOLOGY → DERIVATION → MATHEMATICAL FORM → EXTERNAL AUDIT

Классическая математика не используется как скрытое основание внутреннего вывода.

## 2. Основной методологический принцип

RECENTERING ≠ REDERIVATION.

После каждого существенного вывода обязательны два хода:

1. Reduction — проверить различия, границы, типы, скрытые импорты и возможный круг.
2. Synthesis — вернуть результат в целостность и определить, что нового он позволяет породить в направлении Development.

Редукция без синтетического возврата не считается завершённым математическим ходом.

## 3. Статусы результатов

Каждый существенный результат должен иметь явный статус:

- CANONICAL / PASS — внутренне выведен, проверен и принят.
- CANDIDATE — внутренне получен, но ещё не завершён аудит.
- AUDIT — внешний или внутренний проверочный материал.
- HOLD — открытый мост или недостающий вывод.
- HYPOTHESIS — явно постулированное предположение.
- SUPERSEDED — заменён более поздним выводом.
- RETRACTED — снят после обнаружения ошибки, круга или скрытого импорта.
- NOT DERIVED — не выведен в текущем корпусе.

## 4. Provenance

Ни один результат не должен терять происхождение.

Для каждого канонического математического узла должно быть возможно восстановить:

Origin → Difference → Foundation → Derivation → Result → Audit.

История Git используется как дополнительный provenance-layer и не должна переписываться ради создания более красивой ретроспективной истории.

## 5. Классическая математика

Классические математические объекты, теоремы, функции и эквивалентные формулировки могут использоваться только после независимого ontology-first вывода соответствующей внутренней структуры.

Допустимый порядок:

INTERNAL DERIVATION → CLASSICAL CORRESPONDENCE → EXTERNAL AUDIT.

Недопустимый порядок:

CLASSICAL RESULT → ONTOLOGICAL RENAMING → CLAIMED DERIVATION.

## 6. Внешние гипотезы

Внешняя гипотеза может быть явно постулирована как контрольный слой.

Такой постулат:

- не становится частью основания;
- не может использоваться для скрытого вывода самого себя;
- должен быть явно отмечен как EXTERNAL TEST POSTULATE;
- используется для поиска минимального внутреннего недостающего закона или для falsification pressure.

## 7. Möbius self-audit

Если возникает подозрение на круг, повторяемость без emergence, скрытую классическую подстановку или потерю provenance, выполняется Möbius-return к последнему доказанному факту.

Möbius не означает продолжение редукции.

Его задача — восстановить распознаваемость происхождения и определить lawful следующий ход.

## 8. Development

Development признаётся только при:

NEW EMERGENT PROPERTY + PRESERVED ORIGIN/PROVENANCE.

Количественное изменение, стабилизация, изменение направления или усложнение записи сами по себе не являются Development.

## 9. Архитектура репозитория

- `00_FOUNDATION/` — исходные ontology-first основания и минимальные математические примитивы.
- `01_CANONICAL_MATHEMATICS/` — канонически выведенная математика.
- `02_EXTERNAL_AUDITS/` — внешние проверки, включая классические математические контуры.
- `03_VERIFICATION/` — протоколы внешней верификации и falsification.
- `99_ARCHIVE/` — superseded, retracted и исторические ветви, сохраняемые ради provenance.

## 10. Канонизация

Результат переводится в CANONICAL только после:

1. внутренней проверки derivation chain;
2. Möbius-проверки;
3. проверки отсутствия скрытых импортов;
4. проверки типизации;
5. синтетического возврата;
6. фиксации статуса.

## 11. Запрет ретрофиттинга

Запрещено изменять ранее выведенную внутреннюю структуру только для того, чтобы она совпала с желаемым внешним результатом.

Если внешний объект не совпадает с внутренним выводом, это считается результатом аудита, а не поводом автоматически менять основание.

## 12. Принцип опровержимости

При внешней верификации приоритет имеет поиск минимального контрпримера, а не накопление подтверждающих аналогий.

Сильный внешний тест имеет форму:

ONTOLOGY → DERIVED STRUCTURAL NECESSITY → INDEPENDENT EXTERNAL CHECK.

## 13. RH

Riemann Hypothesis и связанные классические конструкции не являются основанием ontology-first математики SINTEZ.

Любое использование RH должно иметь явно указанный статус:

- external audit;
- external test postulate;
- open identification bridge;
- verified correspondence.

До отдельного доказательства запрещено формулировать внутренние результаты SINTEZ как доказательство RH.

## 14. Основной принцип репозитория

Не выдавать желаемое за действительное.

Красота результата усиливает требование проверки, а не ослабляет его.
